# Edge Case Audit Report
**Date:** 2026-08-04
**Source Tool:** Claude Code (`quality-reviewer` subagent, model: Sonnet 5)

Scope: boundary values, data-driven edge cases, offline/network-failure paths, multi-tab concurrency, input validation, achievement boundaries. Findings already documented in `review-report.md` (L1, B1–B12) were excluded.

## Findings

- **[HIGH]** The 50:50 joker hides options **by string value, not by array slot** — on questions with a duplicated `incorrect_answers` string it over-hides, leaving only the correct answer on screen for 3 coins. `src/App.jsx:572-573` builds `toHide` from `currentShuffledOptions.filter(opt => opt !== correctAns)` (plain strings), and the render at `src/App.jsx:931` does `hiddenOptions.includes(option)` per button. Verified against production data: `src/data/categories/geografija.json:641` (`hr_geo_59`, "Koji je glavni grad Južne Koreje?") has `incorrect_answers: ["Busan","Incheon","Incheon"]`, and `src/data/categories/sport.json:872` (`hr_sport_80`) has `["Karambol","Pikado","Pikado"]`. **Reproduction:** on `hr_geo_59`, click 50:50. `toHide` picks 2 of the 3 incorrect strings, drawn from the pairs `{Busan,Incheon}`, `{Busan,Incheon}`, `{Incheon,Incheon}` — so **2 times out of 3** the pair contains "Busan" plus one "Incheon", and `.includes("Incheon")` matches **both** rendered Incheon buttons, so all 3 incorrect options vanish and "Seul" is the only visible button. Only the 1-in-3 draw picking both Incheon instances behaves as designed. `validateEntry` (`src/utils/questionMerge.js:66-69`) already rejects this pattern for new uploads via a `Set` size check, so this is legacy seed data — but it is live in production today.
- **[HIGH]** Same-account multi-tab (or two devices both open) causes silent last-write-wins loss of coins/XP/achievements, with no reconciliation. `src/App.jsx:233-239`'s persist effect fires on every `globalStats` change and writes the *entire* stats object to both localStorage and Firestore (`syncUserStatsToFirestore`, `src/services/firebase.js:104-116`, spreading `...stats` wholesale into `setDoc(..., {merge:true})` — field-level merge, but each field fully replaced, not incremented). There is **no `storage` event listener and no `visibilitychange`/focus refetch anywhere** in `src/App.jsx` (verified via grep — zero matches), so a tab never learns about another tab's write. **Reproduction:** sign in on Tab A and Tab B (same account). Play a round to completion in Tab A, earning ~20 coins/XP — it syncs immediately. Tab B still holds its pre-round `globalStats` in memory; the moment Tab B's `globalStats` changes at all (even opening a modal that touches it), its stale snapshot overwrites both localStorage and the Firestore `users/{uid}` doc, silently erasing Tab A's progress with no warning to either tab.
- **[MEDIUM]** AdminPanel's user-edit form has no bounds/NaN guard on level/xp, and a negative or zero value silently and **permanently** breaks that player's public Rekordi sync with no error surfaced anywhere. `src/components/AdminPanel.jsx:269-271` does `level: Number(formData.level), xp: Number(formData.xp)` with no `min`/clamp — a blank `<input type="number">` becomes `Number('') === 0`, and nothing stops a negative value. `firestore.rules:38` lets an admin write any shape to `users/{uid}`, so it commits unchecked. Next time that player signs in, their own client calls `syncPublicProfile` (`src/App.jsx:237`, `src/services/firebase.js:162-178`), which reads `stats.level || 1` / `stats.xp || 0` — but `||` only catches `0`, not negatives (`-5 || 1` evaluates to `-5`), so the negative is sent as-is. `firestore.rules:97-100` requires `level >= 1` and `xp >= 0` for `publicProfiles/{uid}`, so that write is **rejected**. `syncPublicProfile`'s catch (`src/services/firebase.js:175-177`) only does `console.error`. Result: that player's Rekordi entry silently freezes forever — never updating level, streak, or achievement count again — invisible to everyone until someone checks the browser console.
- **[MEDIUM]** Login/registration network failures are always mislabeled as wrong credentials, masking real outage/offline scenarios. `src/components/AuthModal.jsx:61-67`'s catch for `handleEmailAuth` never inspects `err.code` — any thrown error (including `auth/network-request-failed` when Firebase is unreachable, or `auth/too-many-requests`) surfaces as `"Neuspješna registracija. Provjerite podatke."` on register or `"Pogrešan email ili lozinka."` on login. `handleGoogleLogin` (`:34-36`) does the same, always showing `"Greška pri prijavi s Google računom."` even when the popup succeeded but the follow-up `syncUserProfile` (`:30`) failed from a dropped connection. A player on a flaky connection who typed everything correctly is told their password is wrong, with no way to tell the difference from the UI.
- **[LOW]** Two questions in production data have a duplicated string within `incorrect_answers` (`hr_geo_59`: `["Busan","Incheon","Incheon"]`; `hr_sport_80`: `["Karambol","Pikado","Pikado"]`), independent of the joker interaction above — even without 50:50, a normal round on these renders two buttons with identical visible text, which is confusing but not functionally broken (both are wrong, either is treated as incorrect). Same root cause and fix as the HIGH finding above.

## Recommended Fixes

- **50:50 duplicate-string bug:** switch `hiddenOptions` to store option *indices* rather than values, or dedupe by `(value, occurrenceIndex)` pairs. Alternatively fix the two dirty JSON entries directly (`geografija.json` id `hr_geo_59`, `sport.json` id `hr_sport_80`) and add a one-off data-lint script — the logic is already effectively encoded in `validateEntry` — to check all 8 category files for the same pattern.
- **Multi-tab race:** add a `storage` event listener that reconciles `globalStats` when another tab writes `triviabong_global_stats` (at minimum, take the max of monotonic fields like xp/coins/totals rather than blindly overwriting), or move to `onSnapshot` for live Firestore sync instead of one-shot writes.
- **AdminPanel numeric fields:** clamp on submit — `Math.max(1, Math.trunc(Number(formData.level) || 1))` for level and `Math.max(0, Math.trunc(Number(formData.xp) || 0))` for xp — and surface `syncPublicProfile`'s rejected writes to the UI by returning its success/failure the way `saveScoreToFirestore` already does, instead of only `console.error`.
- **Auth error masking:** branch on `err.code` (`auth/network-request-failed`, `auth/too-many-requests`, etc.) and show a distinct "check your connection" message rather than folding every failure into "wrong credentials."
