# Architecture Audit Report
**Date:** 2026-08-04
**Source Tool:** Claude Code (`architect` subagent, model: Opus 5)

Scope: module boundaries, state architecture, data layer, persistence/sync, convention drift, test seams. Line-level React lifecycle bugs were explicitly out of scope — those are covered in `review-report.md` (findings B1–B12).

## Findings

- **[HIGH]** `users/{uid}` has three independent, unsequenced writers and no read-back, so `globalStats` has no coherent source of truth. Writers: `src/components/AuthModal.jsx:30,57` (profile fields), `src/App.jsx:236` (full stats object), `src/components/AdminPanel.jsx:267` (level/xp/coins/role). `syncUserStatsToFirestore` (`src/services/firebase.js:108`) writes the whole object with `{merge:true}` and no `increment()` — last-writer-wins per field. Two tabs, or a phone and a laptop, silently revert each other; an admin editing their own row gets clobbered by that account's next gameplay write. The `hasPendingWrites` workaround at `src/services/firebase.js:69-90` is a symptom of exactly this race.
- **[HIGH]** No stats-load choke point and no schema version, so migrations have nowhere to hook. Stats load in two unrelated places with different semantics — `src/App.jsx:122-129` (localStorage, merge-over-defaults) and `src/App.jsx:199-211` (Firestore, spread-over-prev) — plus a third defaults-merge on the write side at `src/services/firebase.js:109`. `DEFAULT_GLOBAL_STATS` (`src/constants/defaultGlobalStats.js:7-21`) has no version field, and merge-over-defaults is precisely what makes legacy data indistinguishable from current data. This is the structural cause behind `review-report.md` finding L1; patching L1 alone leaves the next balance change with the identical hole.
- **[HIGH]** localStorage is device-global, not account-scoped. `triviabong_global_stats` and `triviabong_leaderboards` are single fixed keys (`src/App.jsx:123,142,230,234`) shared by anonymous play and every account ever signed in on that browser. Finding B3 (missing sign-out reset) is the visible symptom; the design flaw is that no per-identity namespace exists, so every future sign-out/switch path must remember to clear by hand.
- **[HIGH]** Rekordi data fetch is unconditional on mount for every visitor, and one of its six queries is an uncapped full-collection scan. `src/App.jsx:253-257` calls `refreshRekordiData()` in a bare mount effect; `getFastestPerfectRounds` (`src/services/firebase.js:226-241`) calls `getDocs(scoresRef)` with **no limit** across all 8 category leaderboards. That function's own comment says "fine for an occasionally-opened records screen, not a hot path" — the call site turned it into a first-paint hot path for signed-out visitors, with read cost growing linearly with every score ever saved.
- **[HIGH]** Single-component design — honest assessment: the *render* split is **not** the liability. The branches are cohesive; splitting them into `LobbyScreen`/`QuizScreen`/`GameOverScreen` would touch ~400 lines for zero defect reduction. That would be churn. The real liability is that all gameplay logic is inseparable from React lifecycle (30 `useState`, 5 effects, 1125 lines), and every one of the 12 prior B-findings is a lifecycle bug no test can reach. Warranted seams in priority order: (a) `useGameRound()` owning round state, the timer effect (`src/App.jsx:260-276`) and every round-transition `setTimeout` (`:487,492,528,532`) — one owner for pending timers kills B1/B5/B6/B10 structurally rather than one patch each; (b) a **pure** `applyAnswer(stats, round, ctx) → {stats, round, events}` replacing `src/App.jsx:331-511`, eliminating the stale-closure class entirely (B2 is literally that bug); (c) `statsStore` + `useStatsSync()` for `src/App.jsx:122-129,190-239`.
- **[MEDIUM]** `CATEGORY_META` — a presentation constant importing lucide-react components (`src/data/categoryMeta.js:1`) — is doing triple duty as the domain category registry. `src/services/firebase.js:204,228` iterates it to decide which Firestore collections to query; `src/utils/achievements.js:19` iterates it for `jack_of_all_trades` completeness. Meanwhile `src/App.jsx:672` uses `getAllCategories()` (`categoryPacks` keys, `src/data/questionsLoader.js:47`) for the same concept. Two competing registries that agree today with nothing enforcing it — and the Firebase service layer now transitively depends on an icon library.
- **[MEDIUM]** Adding a category requires five coordinated edits across four files with no assertion tying them together: `src/data/questionsLoader.js:1-21`, `src/data/categoryKeys.js:8`, `src/data/categoryMeta.js:7`, `src/utils/questionMerge.js:13` (`ID_PREFIXES`), `src/utils/questionMerge.js:27` (`CATEGORY_FILES`). Failure modes differ per omission and none is loud: miss `ID_PREFIXES` and admin upload throws at `questionMerge.js:142`; miss `CATEGORY_META` and the category silently disappears from every Rekordi board. `CLAUDE.md:25` documents four of the five, omitting both `questionMerge.js` entries.
- **[MEDIUM]** Question dedupe boundary (per file) does not match the consumption boundary (aggregate pool). `mergeQuestions` builds `seenText` only from the *target* pack (`src/utils/questionMerge.js:145-146`), but `getAllQuestions()` (`src/data/questionsLoader.js:65`) flattens all packs for `opca_znanje`. **Verified by script: 5 question texts exist in both `opca_znanje.json` and `znanost_i_tehnologija.json`** — `hr_gen_137`/`hr_sci_98` ("koja je najduža kost u ljudskom tijelu?"), `hr_gen_145`/`hr_sci_40`, `hr_gen_152`/`hr_sci_307`, `hr_gen_167`/`hr_sci_86`, `hr_gen_178`/`hr_sci_20`. Both copies are in the aggregate pool, so a single Opće znanje round can serve the same question twice. (No duplicate `id`s exist.)
- **[MEDIUM]** Cross-artifact invariants hardcoded in `firestore.rules` with a silent-failure mode. `firestore.rules:107` caps `achievementCount <= 30` — exactly the current catalog size (30 entries in `src/constants/achievements.js`, verified 1:1 against `ACHIEVEMENT_CHECKS`). `firestore.rules:66` caps `score <= 10000`, hand-derived from `gameBalance.js`. Adding a 31st achievement, or raising `BASE_SCORE`, makes writes permission-denied — and both write paths swallow it (`src/services/firebase.js:175` catch→`console.error`; `src/App.jsx:236` fire-and-forget), so it breaks invisibly in production. Related: `ADMIN_EMAIL` is **triplicated** — `src/App.jsx:53`, `firestore.rules:20`, `api/questions.js:24` — while `CLAUDE.md:39` documents only two of the three.
- **[MEDIUM]** Bundle: one 1.71 MB JS chunk, no code splitting anywhere (zero `React.lazy`/dynamic `import()` in `src/`). Every visitor downloads all **3542 questions / ~1.29 MB of raw JSON** (static imports at `src/data/questionsLoader.js:1-8`) plus the 1033-line `AdminPanel` reachable by exactly one email address (static import at `src/App.jsx:31`). `vite.config.js` has no `manualChunks`. Verified against `dist/assets/index-COgqSwNs.js`. Doc drift: `CLAUDE.md:25,27` say "~500KB" and "all 1492 questions" — **2.4× stale**. Also `framer-motion` is a declared dependency with **zero imports** anywhere in `src/` or `api/`.
- **[MEDIUM]** Testing architecture has no seam to test against. No unit test runner in `package.json` at all, and the Firebase config is a hardcoded object literal (`src/services/firebase.js:29-37`) — **zero `import.meta.env` usage anywhere in `src/`**, no `connectFirestoreEmulator`/`connectAuthEmulator`. The app physically cannot be pointed at the emulator, which is why the only E2E verification writes to live production Firestore, and why the emulator workflow `CLAUDE.md:39` recommends can cover rules but never the app. Already-pure, already-critical, entirely untested: `src/utils/leveling.js` (an `xpForLevel` monotonicity + curve-boundary test is exactly what would have caught L1), `src/utils/achievements.js`, `src/utils/questionMerge.js`, `src/data/categoryKeys.js`.
- **[LOW]** Dead prop coupling: `src/App.jsx:1106-1117` passes `globalStats`, `setGlobalStats`, `leaderboards`, `setLeaderboards` to `AdminPanel`, whose signature is `AdminPanel({ onClose })` (`src/components/AdminPanel.jsx:21`). All four silently ignored. Reads as though the admin panel mutates live player state and shares the leaderboard cache; it does neither.
- **[LOW]** Admin gate drift vs. `CLAUDE.md:39`, which states the panel opens only when the email matches *and* the path is exactly `/admin`. The header Admin button (`src/App.jsx:751-760`) renders on **any** path for the admin email and calls `setShowAdminPanel(true)`; the render gate (`src/App.jsx:1105`) checks only `showAdminPanel && isAdminUser`. `isAdminPath()` constrains only the auth-listener auto-open (`:215`). Low security impact (the real boundary is `firestore.rules`), but the documented invariant is not the actual one.

### Verified clean — reported as signal, not filler

The `gameBalance.js` single-source-of-truth convention **is** upheld: `GuideModal.jsx:3-17,75-115` derives every displayed number from the constants, including the worked score example, so the guide cannot drift from play. The `questionMerge.js` browser/server-shared-logic convention **is** upheld: `api/questions.js:16-22` imports the same module `AdminPanel.jsx:17` does, no duplicated validation, and the server re-validates rather than trusting the client preview. `categoryKeys.js` is correctly separated from `questionsLoader.js` for the documented serverless-bundle reason. `api/questions.js:43-46` verifies issuer *and* audience, not just signature. `getCategoryDetails` (`src/App.jsx:66-77`) correctly resolves through the alias map before the meta lookup. The achievements catalog/checks are exactly 1:1 with no orphans in either direction.

**UNVERIFIED:** The app and E2E scripts were not run. Bundle figures come from the checked-in `dist/` (built 2026-08-04) plus static-import analysis, so they may lag `HEAD` by a commit; the "no code splitting" conclusion is from source (`vite.config.js`, zero dynamic imports) and is independent of that.

## Recommended Fixes

- **Source of truth / competing writers.** Move stats out of the profile doc: `users/{uid}` keeps auth-profile fields only, stats move to `users/{uid}/state/stats`. Removes the write race the `hasPendingWrites` workaround exists for, and lets `firestore.rules` validate the stats shape independently. For cross-device safety, write monotonic counters with `increment()` rather than whole-object `setDoc(..., {merge:true})`.
- **Schema versioning.** New `src/services/statsStore.js` as the *only* stats load/save path: `loadStats({uid})`, `persistStats(stats, {uid})`, and an ordered `MIGRATIONS = [{to: 1, fn}, ...]` applied against the **raw** persisted object before any defaults merge. Add `statsVersion: N` to `DEFAULT_GLOBAL_STATS`. Then `App.jsx:122-129`, `:199-211` and `firebase.js:104-116` all collapse into it — one hook point for L1 and every future rebalance.
- **Account-scoped storage.** `const statsKey = (uid) => \`triviabong_global_stats:${uid ?? 'anon'}\`` inside `statsStore`. Sign-out then needs no explicit reset — it just reads a different slot.
- **Rekordi cost.** Drop the mount effect; fetch on first lobby paint behind an `IntersectionObserver` or on modal open. Give `getFastestPerfectRounds` a `limit()` per category with a composite index (`isPerfect ASC, elapsedMs ASC`), or denormalize into a single `records/summary` doc updated on score save.
- **One category registry.** In `categoryKeys.js`: `export const CATEGORY_KEYS = ['geografija', ...]`. Have `categoryPacks`, `CATEGORY_META`, `ID_PREFIXES`, `CATEGORY_FILES` all be built from or asserted against it (a dev-only `console.assert` on key-set equality at module load costs nothing and turns four silent drifts into one loud one). `firebase.js` and `achievements.js` import `CATEGORY_KEYS`, not `CATEGORY_META` — which also removes lucide-react from the service layer's dependency graph.
- **Aggregate dedupe.** `getAllQuestions()` → dedupe by normalized question text before returning; and in `api/questions.js`'s add path, when the target pack is visible through an aggregate, build `seenText` from every pack, not just the target.
- **Rules invariants.** Replace the magic `30` at `firestore.rules:107` with a comment naming `src/constants/achievements.js` as its source, and add a CI check (`node -e` counting `id:` occurrences vs. the rules literal) — same for `score <= 10000` vs. `gameBalance.js`. Separately, stop swallowing the write failure: surface a one-line console warning distinguishing `permission-denied` from network errors at `firebase.js:175`.
- **Bundle.** `const AdminPanel = React.lazy(() => import('./components/AdminPanel'))` behind the existing `showAdminPanel && isAdminUser` gate — that alone removes the admin surface and its transitive deps from the visitor bundle. For questions, convert `categoryPacks` to `() => import('./categories/x.json')` and make `getQuestionsByCategory` async, or at minimum add `manualChunks` so question data is a separate cacheable chunk. Drop `framer-motion` from `package.json`.
- **Test seams.** Add Vitest (already a Vite project, near-zero config) and start with four pure-module suites: `xpForLevel` monotonicity + tier-boundary + `computeLevelFromXp` round-trip; `computeDayStreakUpdate` across a DST boundary and a backward clock; `mergeQuestions` idempotency + cross-pack duplicate rejection; `resolveCategoryKey` over every alias. Then extract `applyAnswer()` as a pure function and test the scoring/streak/xp pipeline directly — the seam that converts most B-findings from "reproducible only by hand in a browser" to "a failing assertion."
- **Firebase config via env.** Read `firebaseConfig` fields from `import.meta.env.VITE_FIREBASE_*` with the current literals as fallbacks (the key is public, so no secret handling needed), plus `if (import.meta.env.VITE_USE_EMULATOR) connectFirestoreEmulator(db, 'localhost', 8080)`. That single change lets `golden-path.mjs` stop writing to the production leaderboard and makes the E2E check safe to run in CI.
